# 災害VC運営シミュレーター（ブラウザ版）

善通寺市災害ボランティアセンターの1日を、**職員がひとりで20分ほどで体験できる**ゲームです。

kintoneによく似た画面をゲームの中に再現しているので、
災害VCの流れと「自分の入力が次の班にどう届くか」を、操作しながら理解できます。

**本番のkintoneには一切つながっていません。** 登場する氏名・住所・電話番号はすべて架空です。

---

## ファイルの中身

| ファイル | 役割 | さわる頻度 |
|---|---|---|
| `index.html` | 画面の見た目 | ときどき |
| `game.js` | ゲームの動き（プログラム本体） | あまり |
| `config.js` | **シナリオ・登場人物・資機材などの設定** | **ここをよく調整する** |

調整したいことのほとんどは `config.js` の文章や数字を書きかえるだけでできます。
プログラム（`game.js`）は読めなくても大丈夫です。

---

## まず手元で動かしてみる

1. 3つのファイル（`index.html` `config.js` `game.js`）を**同じフォルダ**に置く
2. `index.html` をダブルクリックしてブラウザで開く

これだけで動きます。インターネットにつながっていなくても動きます。
スマホで見たいときは、下の「GitHub Pagesで公開」に進みます。

## ゲームの流れ（10場面）

マニュアル「3. 活動の流れ」の順番どおりに進みます。

| 場面 | 担当班 | ゲームでやること |
|---|---|---|
| ①ニーズ受付 | ニーズ班 | 電話を2件受け、**聞き取って受付シートを埋め**、それがkintoneに入力される様子を見る |
| ②現地調査 | 現地調査班 | **出発前に注意点を確認**し、現場で写真を撮り、被災状況・必要人数・資機材が入力される様子を見る |
| ③当日受付 | 当日受付班 | QR→フォームで登録されるのを確認し、1名だけ代行入力する |
| ④オリエンテーション | マッチング班 | 動画を上映し、**ローカルルールを口頭で伝える** |
| ⑤マッチング | マッチング班 | ニーズとボランティアを組み合わせ、活動依頼書を発行する |
| ⑥資機材・送り出し | 資機材・送出し班 | 資機材をそろえ、**出発前の体調・装備を確認**して送り出す |
| ⑦ボランティア活動 | ― | （午後のイベントが起こります） |
| ⑧帰着 | マッチング班 | **ねぎらい、けが・事故・ヒヤリハットを確認する** |
| ⑨活動報告 | マッチング班 | 口頭報告を聞き取り、活動報告アプリに入力する |
| ⑩活動後の手続き | マッチング班 | 活動証明書を発行する／高速道路の無料措置の相談に答える |

最後に**ふりかえり画面**が出て、○×と解説が表示されます。

### ①の聞き取りについて

実物の `ニーズ受付シート` に「**聞き取り後** kintone に入力してください」と書かれているとおり、
ゲームでも**聞き取り → 受付シート → kintone入力**の二段構えにしています。

- プレイヤーがやるのは「**何を聞くか**」の選択（質問候補から選んでタップ）
- 聞いた答えは、画面左の**受付シートに自動で書き取られます**
- **聞かなかった項目は空欄のまま残ります**
- 聞ける回数には上限があります（相手はご高齢で、長電話は負担になるため）
- 聞き取りのあと、受付シート下段の「**受付時の判断**」（現地調査の要否／危機介入／見守り）を自分でチェック
- kintoneへの入力は、**シートの内容が1項目ずつ自動で入る様子を見ます**（下の「文字入力はありません」を参照）

紙の受付シートを印刷して準備する必要はありません。画面の中に再現しています。

**画面の幅によって、シートの見せ方が変わります。**

| | シートの表示 |
|---|---|
| パソコン（761px以上） | 左に固定表示。見ながら右のフォームに入力できます |
| スマホ（760px以下） | 右下の「**📄 受付シート**」ボタンで重ねて開きます。閉じると元の画面に戻ります |

スマホで上下に並べると、シートを見ながら入力できません。
**紙を手に取って見て、置いて入力する**のに近い動きになるよう、重ね表示にしています。

聞き取り中は、質問に答えてもらうたびに
「✏️ 受付シートの『氏名』『電話番号』に書き取りました」と表示され、シート側では鉛筆で書かれるアニメーションが流れるので、
シートを開いていなくても、何が記録されたかが分かります（ボタンも一瞬ふくらみます）。

## わざと仕込んである「つまずき」

マニュアル「6. 困ったときは」に書かれている、**実際に現場で起きる失敗**をそのまま体験できるようにしています。

| 仕込み | 学べること |
|---|---|
| 聞ける回数に上限がある | 何を優先して聞くか。**聞かなかったことは記録に残らない** |
| 「費用や謝礼はご用意できますか」という質問候補 | 災害ボランティアの活動は無償。聞いてはいけない質問がある |
| 1件目の依頼者は名簿にいない／2件目はいる | 名簿にいない方は自動で登録され、いる方は「取得」で出てくる。**その違いが入力画面で見える** |
| 2件目に危機介入をチェックすると | 全部に付けるのは、何も付けないのと同じ |
| 1件目で氏名・電話・住所を聞き漏らすと | 名簿に登録できず、**折り返し電話**になる（減点） |
| 現地の聞き取りメモに、一人暮らし・持病・断水の記述 | **危機介入の必要性**にチェックを入れる判断 |
| 現地調査に出る前の注意点（6項目） | ひとりで行かない／足元と頭上／**写真は必ず断ってから撮る**／家財を勝手に動かさない／見えるものだけで判断しない／その場で安請け合いしない |
| 危機介入ありと判断した直後 | **記録して次の班に回すだけでは間に合わない。**受付の時点で班長・センター長に報告・相談し、他機関につなぐ相談もする |
| 受付シートの「現地調査 必要／不要／要相談」 | **この選択が実際に進行を変えます。**「不要」にすると現場に行かず、電話の聞き取りだけで人数と資機材を決めることになります |
| 危機介入の現場を「不要」にすると | 全件は回れなくても、**危機介入ありと判断した現場は必ず見に行く** |
| ボランティアが1名足りない | 人が足りない日に、どのニーズを優先するか |
| 必要人数を超えて割り当てられる | **必要人数はあくまで見立て。**土砂の量が読めない現場は多めに入ってもらう判断もある |
| 人数がそろわない現場 | そろわなくても送り出す／翌日に回す。どちらもあり得る。**危機介入の現場から人を抜くのは順番が逆** |
| 活動先が決まらなかったボランティア | **帰ってもらうのが最初の選択肢ではない。**現場に追加、センター業務、翌日の依頼 |
| 保険未加入のボランティアが1名まざっている | 断って帰ってもらうのではなく、**その場で加入につなぐ**（災害時のオンライン加入）。つなげば人手不足も解消する |
| 高速道路の無料措置を頼まれる | **原則は本人が発行サイトで申請・印刷**し、VCは活動確認印を押す |
| そのボランティアはスマホもプリンターも使えない | 原則を伝えて終わりにせず、**できない方の分はVCが代行して申請・印刷する** |
| 午後に同じ内容の電話がかかってくる | **二重登録の罠**（登録の前にまず検索） |
| 活動報告はニーズのレコードから開く | アクションボタン経由でないとニーズIDがひもづかない（画面で説明） |
| 「完了」で保存したあとの確認 | ニーズ管理側の進捗状況も変えないと、翌日また人が送られる |

## GitHub Pages で公開する手順

> スマホの実機で開けるようにするには、インターネット上に置く必要があります。
> GitHub Pages なら無料で、URL（`https://○○.github.io/△△/`）が手に入ります。

### 初回だけ：リポジトリを作る
1. GitHub にログイン → 右上の「＋」→ **New repository**
2. リポジトリ名を入力（例：`saigai-vc-game`）
3. **Public** を選ぶ（Pages は Public で使うのが簡単）
4. **Create repository**

### ファイルを置く
1. 作ったリポジトリの画面で **Add file → Upload files**
2. `index.html` `config.js` `game.js` の3つをドラッグして上げる
3. 下の **Commit changes** を押す

### Pages を有効にする
1. リポジトリの **Settings** → 左メニューの **Pages**
2. 「Build and deployment」の Source を **Deploy from a branch**
3. Branch を **main**、フォルダは **/(root)** を選んで **Save**
4. 1〜2分待つと、ページ上部に公開URLが出る

このURLをQRコードにして研修資料に載せると、職員がその場で開けます。

### 直したいとき（2回目以降）
- `config.js` などを直して、同じ場所に Upload して Commit するだけ
- 1〜2分でURLの中身が新しくなります

## よくある調整（config.js）

`config.js` をテキストエディタで開いて、次の場所を書きかえます。

- **電話の内容をかえる** … `CALLS` の `lines`（相手のセリフ）
- **聞き取りの質問をかえる／増やす** … `CALLS` の `questions`
  - `q` が質問文、`a` が相手の答え
  - `set:{...}` は受付シートの欄（`name` `tel` `addr` `state` `when`）に入る内容
  - `memo:"…"` は「現地の様子・補足メモ」欄に箇条書きで入る
  - `need:true` … これを聞かないと受付が成立しない基本情報
  - `vital:true` … 危機介入の判断に必要な情報
  - `bad:"理由"` … 聞くべきでない質問。選ぶと理由が表示され、減点になります
- **聞ける回数をかえる** … `CALLS` の `askBudget`（減らすと難しくなります）
- **受付時の判断の正解** … `CALLS` の `judge`（`survey` `crisis` `watch`）
- **現場の状況をかえる** … `CALLS` の `survey` の `memo` `people` `equip` `memoTip`（特記事項に入る文章）
- **危機介入が必要な設定にする／しない** … `survey` の `crisis`（`true` / `false`）と `crisisWhy`
- **ボランティアの人数・保険・軽トラをかえる** … `VOLUNTEERS`
  - ここの人数を減らすと**難しく**なります（優先順位の判断がシビアになる）
  - `ins` を `"未加入"` にすると、その人は送り出せなくなります
- **名簿の初期データ** … `ROSTER`（**ここに実在の方の情報を入れないでください**）
- **資機材の選択肢** … `EQUIPMENT`
- **はじめの説明** … `INTRO`

数字や文章を直したら保存して、ブラウザを再読み込みすれば反映されます。

## 使い方の想定

このゲームは、研修の**第1層（ひとりで概要をつかむ）**にあたります。

1. **このゲーム** … 一人で、災害VCの流れと各班の作業を理解する ← いまここ
2. 班別ドリル … 自分の班の操作を、本番のkintoneで練習する
3. 全体訓練 … 5班に分かれて、時間を圧縮した図上訓練を行う

ゲームをクリアしてから「災害VC kintone操作マニュアル」を読むと、
どの手順が何のためにあるのかが分かった状態で読めます。

## 文字サイズ

画面右上の「**文字**」ボタンを押すたびに、**標準 → 大 → 特大** と切り替わります。
選んだ大きさはブラウザに保存され、次に開いたときも引き継がれます。

年代によって読みやすい大きさが違うので、研修の冒頭で「文字が小さければ右上のボタンで大きくできます」
と一言添えてください。

全体の基準そのものを変えたいときは、`index.html` の末尾にある「文字サイズ」ブロックの
`html{font-size:100%;}` の数字を変えてください（`110%` にすれば全体が1割大きくなります）。
個別の大きさもすべてこのブロックにまとまっています。

## いま1日のどこにいるか

画面上部に、①ニーズ受付 → ⑧ふりかえり の帯を常時表示しています。

## 文字入力はありません

**最後まで触ってもらうことを最優先**にしているため、キーボード入力は一切ありません。

### kintoneの入力画面は「見る」画面です

ニーズ管理・現地調査・活動報告・活動証明書の4画面は、
ボタンを1回押すと**1項目ずつ順番に入力されていきます**。

**1項目入力するごとに止まります。**その欄のすぐ下に吹き出しが出て、
「なぜそう入力したのか」が表示されます。読んでから「次へ」を押すと、次の項目に進みます。
入力中の欄は黄色く光り、吹き出しには「3 / 8」のように進み具合も出ます。

自分のペースで読み進められるので、速すぎて分からないということはありません。
文字が入力されていく速さは `config.js` の `TYPE_SPEED` で変えられます（`1` が標準、`2` で半分の速さ）。

各項目には、**その値がどこから来たのか**が出ます。ここがこのゲームの中心です。

| 表示 | 意味 |
|---|---|
| 📄 受付シート | 紙から書き写した |
| 💻 名簿アプリ / 当日受付 | 別のアプリから自動で入った（ルックアップ） |
| 🔍 現地で確認 | 現場を見て判断した |
| 🗣 口頭の報告 | ボランティアが口で言ったことを書き取った |
| ⚙ 自動 | システムが計算した（活動期間など） |

「朝QRコードで受付した情報が、夕方の活動証明書までつながっている」といった
**アプリ同士のつながり**が、入力の様子を見るだけで分かります。

### 判断はkintone以外の場面に集約しています

考えて選ぶ場面は、**紙の受付シートと、人とのやりとり**に寄せました。

- 聞き取りで何を聞くか
- 受付シートの「受付時の判断」（現地調査の要否／危機介入／見守り）
- 班長・センター長への報告
- ボランティアのマッチング
- 帰着時の対応、証明書の3択問題

kintoneの画面は「こう入力されるのか」を見る場所、
紙と会話は「自分で考える」場所、という分け方です。

### 押すべきボタンには 👆 が出ます

出るのは**次に進むための1つのボタンだけ**です。
聞き取りの質問や3択の設問は、自分で考えて選ぶところなので指は出しません。

## 「← もどる」ボタン

画面右上の「← もどる」で、**ひとつ前の場面をやり直せます**。

登録したレコードや、ふりかえりの○×も、その場面に入る直前の状態まで巻き戻ります。
（例：ニーズを保存したあとに戻ると、そのニーズは未保存の状態に戻ります）

戻れるのは場面の先頭までです。聞き取りの途中の1問だけを取り消すことはできません。

## オリエンテーションについて

考え方は「**全国共通のことは動画に任せ、職員はローカルルールを口頭で補う**」です。

画面に上映用のスクリーンが出て、▶ を押すと上映が終わります。
**実際の動画は再生しません**（外部サイトへは飛びません。オフラインでも動きます）。
体験してほしいのは動画の中身ではなく、「動画を上映し、そのあと口頭で補う」という**手順**だからです。

- `VIDEO_TITLE` `VIDEO_LEN` … スクリーンに表示される題名と長さ
- `VIDEO_POINTS` … 動画が扱う内容（＝口頭で繰り返さなくてよいこと）
- `LOCAL_RULES` … 口頭で伝えること。`must:true` は伝え漏れると減点になります

集合時間・通行止め・体調不良の申し出・依頼書を超える依頼への対応の4つを `must:true` にしています。
災害や地域に合わせて増減してください。

## 採点のしくみ（AIは使っていません）

ふりかえりの○×は、すべて `game.js` の中の**単純な条件分岐**で判定しています。
インターネットにも、AIにも、一切つながっていません。

- 「依頼内容を具体的に書いた」… **入力した文字数が15文字以上かどうか**だけを見ています
- 「必要人数や資機材の根拠を、特記事項に残した」… 特記事項が10文字以上かどうか。
  **必要人数の数字そのものは採点していません**（現場の状況・ボランティアの集まり具合・
  その日の体制で変わるため、正解の数字が存在しないからです）
- 「口頭で聞き取った内容も記録した」… 報告内容に「水／断水／洗い／押し入れ／濡れ／奥」のいずれかの語が含まれるか
- それ以外… 選択肢を選んだか、必要人数が足りているか、といった数の比較

つまり**文章の中身は判定していません**。「あああああああああああああああ」と15文字書けば○になります。
研修で使うぶんには、短すぎる記録に気づいてもらえれば十分と考えてこの作りにしています。

判定を変えたいときは `game.js` の `mark(` で始まる行を探してください。

## 見た目について（意図的にやっていないこと）

**kintoneの各アプリ画面は、あえてかっこよくしていません。**

このゲームの狙いは「本番のkintoneを開いたとき『これ見たことある』となること」です。
入力画面をスタイリッシュにすると本物との見た目の差が開き、訓練としての効果が落ちます。
地味なのは欠陥ではなく、そういう作りです。

作り込んでいるのは、タイトル・電話・オリエンテーション・ふりかえりなど、
**kintone以外の場面**だけです。

### 登場人物はシルエットのみ

顔は描いていません。特定の誰かではなく「そういう立場の人」として見えるようにしています。
被災された方を写実的に描くのは、訓練教材としては扱いが難しいためです。

シルエットは `game.js` の `SIL` にSVGで定義しています（`elderF` `manM` `elderM` `staff` `volun`）。
電話の相手は `config.js` の `CALLS` の `sil` で指定します。

### タイトルのドット絵

`game.js` の `PIXFONT`（5×7の欧文ドットフォント）で描いています。
`pixText('SAIGAI VC', 6)` の文字列を変えれば、別の文字にできます。**英数字と `-` のみ対応**です。
漢字はドット絵にすると読みにくくなるため、日本語タイトルは通常の書体を角ばらせて処理しています。

## 制度に関するメモ

- **ボランティア活動保険**は通常、市区町村社協の窓口で加入しますが、災害が発生するとオンライン加入が
  実施されます。ゲームでもその流れで作っています。窓口加入の流れで訓練したい場合は、
  `config.js` の `ONLINE_INSURANCE` を `false` にしてください。
- **高速道路の無料措置**は、対象範囲・手続きが災害ごとに国土交通省・NEXCOから示されます。
  ゲーム内でもその旨を表示しています。

参考：ボランティア活動保険 https://www.saigaivc.com/insurance/ ／
災害ボランティア車両 高速道路通行証明書 https://exvolunteer.jp/

## 注意

- 点数は**運営の手順**についてのものです。実際の災害では、対応できた件数の多さで良し悪しが決まるわけではありません。ふりかえり画面にもその旨を明記しています。
- `config.js` に登場人物を追加するときは、**必ず架空の氏名・住所・電話番号**にしてください。公開URLは誰でも見られます。
