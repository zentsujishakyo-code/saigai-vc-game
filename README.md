# 災害VC運営シミュレーター

善通寺市災害ボランティアセンターの1日を、**職員がひとりで20分ほどで体験できる**ブラウザ用の訓練教材です。

**公開URL** https://zentsujishakyo-code.github.io/saigai-vc-game/

kintoneによく似た画面をゲームの中に再現しているので、災害VCの流れと
「自分の入力が次の班にどう届くか」を、画面を見ながら理解できます。

> **本番のkintoneには一切つながっていません。**
> 登場する氏名・住所・電話番号はすべて架空です。安心して間違えてください。

## まず動かす

`index.html` `config.js` `game.js` を**同じフォルダ**に置いて、`index.html` をダブルクリックするだけです。
サーバーもインストールも要りません。**インターネットにつながっていなくても動きます。**

スマホで見せたいときは、上の公開URLを開いてもらうか、下の「GitHub Pages で公開・更新する」を参照してください。

## ゲームの流れ

マニュアル「3. 活動の流れ」の順番どおりに進みます。

| 場面 | 担当班 | やること |
|---|---|---|
| ①ニーズ受付 | ニーズ班 | 電話を2件受け、**何を聞くか選び**、受付シートを埋め、kintoneに入力する |
| ②現地調査 | 現地調査班 | **出発前に注意点を確認**し、写真を撮り、状況・必要人数・資機材を入力する |
| ③当日受付 | 当日受付班 | QR→フォームで登録されるのを確認し、1名だけ代行入力する |
| ④オリエンテーション | マッチング班 | 動画を上映し、**ローカルルールを口頭で伝える** |
| ⑤マッチング | マッチング班 | ニーズとボランティアを組み合わせ、活動依頼書を発行する |
| ⑥資機材・送り出し | 資機材・送出し班 | 資機材をそろえ、**出発前の体調・装備を確認**して送り出す |
| ⑦ボランティア活動 | ― | （午後にイベントが起こります） |
| ⑧帰着 | マッチング班 | **ねぎらい、けが・事故・ヒヤリハットを確認する** |
| ⑨活動報告 | マッチング班 | 口頭報告を聞き取り、活動報告アプリに入力する |
| ⑩活動後の手続き | マッチング班 | 活動証明書を発行する／高速道路の無料措置の相談に答える |

最後に**ふりかえり画面**が出ます。

画面のいちばん上に、①〜⑧の帯を常時表示しています。済んだ場面は緑、いまの場面はオレンジです。

## 設計の考え方

### 1. 文字入力はありません

最後まで到達してもらうことを最優先にしているため、**キーボード入力は一切必要ありません**。
やることは「選ぶ・押す」だけです。

### 2. 1件目は「見る」、2件目は「自分でやる」

ニーズ受付と現地調査は、それぞれ2件あります。

**1件目**は、入力される様子を見てもらいます。**1項目ずつ止まり**、その欄のすぐ下に吹き出しが出て
「なぜそう入力したのか」が表示されます。読んでから「次へ」を押すと次に進みます。
入力中の欄は黄色く光り、吹き出しには「3 / 8」のように進み具合も出ます。

**2件目**は「**今度は自分でやってみましょう**」と、同じことを自分で操作します。

1. 選択肢を**選ぶ**（受付方法・被災状況・必要人数など）
2. 「**書き写す**」を押す（氏名・依頼内容・特記事項）
3. 「**取得**」を押す（名簿アプリから電話番号・住所を呼び出す）
4. 「**保存**」を押す

画面の上に**手順のチェックリスト**が出て、終わった項目に ✓ が付きます。
足りないまま保存を押すと、どこが足りないかをやさしく教えます。

> **危機介入の必要性だけは手順に入れていません。**現場の様子から自分で判断してもらいます。

### 3. その値が「どこから来たのか」を見せる

入力される各項目には、出どころのラベルが付きます。ここがこの教材の中心です。

| 表示 | 意味 |
|---|---|
| 📄 受付シート | 紙から書き写した |
| 💻 名簿アプリ / 当日受付 | 別のアプリから自動で入った（ルックアップ） |
| 🔍 現地で確認 | 現場を見て判断した |
| 🗣 口頭の報告 | ボランティアが口で言ったことを書き取った |
| ⚙ 自動 | システムが計算した（活動期間など） |

「朝QRコードで受付した情報が、夕方の活動証明書までつながっている」といった
**アプリ同士のつながり**が、入力の様子を見るだけで分かります。

### 4. 紙・パソコン・口頭を色で分ける

「これは紙？パソコン？口で言うだけ？」が分からないと、流れが頭に入りません。

| 色 | 媒体 | 見出し |
|---|---|---|
| 🔵 **青** `#1565c0` | kintone アプリ | 💻 入力すると記録が残ります |
| 🟠 **オレンジ** `#a8670e` | 紙の書類 | 📄 手書きで記入します／印刷して手渡します |
| 🟣 **紫** `#5b2d86` | 口頭でのやりとり | 🗣 このままでは記録に残りません |

色相を大きく離してあります。色を変えるときは `index.html` の先頭にある
`--kin` `--paper` `--talk` の3つを直せば全画面に反映されます。
**色だけに頼らず、アイコン（💻📄🗣）と文字も併記**しています。

### 5. 判断は kintone 以外の場面に集めている

kintoneの画面は「こう入力されるのか」を見る場所、紙と会話は「自分で考える」場所、という分け方です。
考えて選ぶ場面は次のとおりです。

- 聞き取りで何を聞くか（回数に上限あり）
- 受付シートの「受付時の判断」（現地調査の要否／危機介入／見守り）
- 班長・センター長への報告
- ボランティアのマッチング
- 帰着時の対応、証明書まわりの設問

### 6. ふりかえりに点数はつけません

**点数・○×・パーセント表示は一切ありません。**点取りゲームになっては意味がないためです。
最後のふりかえりは3つに分かれます。該当がないグループは表示されません。

| | 見出し | 中身 |
|---|---|---|
| 💡 | ここは覚えて帰ってください | できていなかったこと。責める書き方はしていません |
| 💬 | 職場で話し合ってみてください | **正解がひとつではない場面**。選んだ対応もあり得ます |
| ✓ | できていたこと | — |

判定は `game.js` の中の**単純な条件分岐**です。選択肢を選んだか、人数が足りているかといった比較だけで、
インターネットにもAIにも一切つながっていません。
変えたいときは `game.js` の `mark(` で始まる行を探してください。
第4引数に `'ok'` `'point'` `'think'` を書くと、表示される場所が変わります。

### 7. その他の配慮

| 機能 | 内容 |
|---|---|
| **文字サイズ** | 右上の「文字」ボタンで **標準 → 大 → 特大**。ブラウザに保存され次回も引き継がれます |
| **← もどる** | ひとつ前の場面をやり直せます。登録したレコードもふりかえりも巻き戻ります |
| **👆 の案内** | 次に押すボタンを指します。**自分で考えて選ぶ場面には出しません** |
| **受付シート** | パソコンでは左に固定表示。スマホでは右下の「📄 受付シート」ボタンで重ねて開きます |
| **鉛筆アニメーション** | 聞き取った内容が、シートに手書きされる様子を表示します |

## わざと仕込んである「つまずき」

マニュアル「6. 困ったときは」に書かれている、**実際に現場で起きる失敗**を体験できるようにしています。

### ニーズ受付

| 仕込み | 学べること |
|---|---|
| 聞ける回数に上限がある | 何を優先して聞くか。**聞かなかったことは記録に残らない** |
| 「費用や謝礼はご用意できますか」という質問候補 | 災害ボランティアの活動は無償。聞いてはいけない質問がある |
| 1件目の依頼者は名簿にいない／2件目はいる | 名簿にいない方は登録が必要。**その違いが入力画面で見える** |
| 氏名・電話・住所を聞き漏らすと | 名簿に登録できず、**折り返し電話**になる |
| 2件目に危機介入をチェックすると | 全部に付けるのは、何も付けないのと同じ |
| 危機介入ありと判断した直後 | **記録して次の班に回すだけでは間に合わない。**受付の時点で班長・センター長に報告する |

### 現地調査

| 仕込み | 学べること |
|---|---|
| 出発前の注意点6項目 | ひとりで行かない／足元と頭上／**写真は必ず断ってから撮る**／家財を勝手に動かさない／見えるものだけで判断しない／その場で安請け合いしない |
| 受付シートの「現地調査 必要／不要／要相談」 | **この選択が実際に進行を変えます。**「不要」にすると現場に行かず、電話の聞き取りだけで判断することになります |
| 危機介入の現場を「不要」にすると | 全件は回れなくても、**危機介入ありと判断した現場は必ず見に行く** |

### マッチング・送り出し

| 仕込み | 学べること |
|---|---|
| 保険未加入のボランティアが1名まざっている | 断って帰ってもらうのではなく、**その場で加入につなぐ**（災害時のオンライン加入） |
| ボランティアが足りない | 人が足りない日に、どのニーズを優先するか |
| 必要人数を超えて割り当てられる | **必要人数はあくまで見立て。**多めに入ってもらう判断もある |
| 人数がそろわない現場 | そろわなくても送り出す／翌日に回す。どちらもあり得る。**危機介入の現場から人を抜くのは順番が逆** |
| 活動先が決まらなかったボランティア | **帰ってもらうのが最初の選択肢ではない。**現場に追加、センター業務、翌日の依頼 |

### 活動後

| 仕込み | 学べること |
|---|---|
| 午後に同じ内容の電話がかかってくる | **二重登録の罠**（登録の前にまず検索） |
| 帰ってきたボランティアへの対応 | 記録より先に、**ねぎらいと安全確認** |
| ヒヤリハットの申し出 | 休んでもらい、必要なら受診を勧め、**記録に残す** |
| 活動報告はニーズのレコードから開く | アクションボタン経由でないとニーズIDがひもづかない |
| 「完了」で保存したあとの確認 | ニーズ管理側の進捗状況も変えないと、翌日また人が送られる |
| 高速道路の無料措置を頼まれる | **原則は本人が発行サイトで申請・印刷**し、VCは活動確認印を押す |
| そのボランティアはスマホもプリンターも使えない | 原則を伝えて終わりにせず、**できない方の分はVCが代行する** |

## config.js でできる調整

`config.js` をテキストエディタで開いて、次の場所を書きかえます。
直したら保存して、ブラウザを再読み込みすれば反映されます。

### シナリオ

| 設定 | 内容 |
|---|---|
| `CALLS[].lines` | 電話の相手のセリフ |
| `CALLS[].questions` | 聞き取りの質問候補。`q`=質問文、`a`=答え、`set:{...}`=受付シートに入る内容、`memo`=補足メモ欄に入る内容 |
| `CALLS[].questions[].need` | これを聞かないと受付が成立しない基本情報 |
| `CALLS[].questions[].vital` | 危機介入の判断に必要な情報 |
| `CALLS[].questions[].bad` | 聞くべきでない質問。選ぶと理由が表示されます |
| `CALLS[].askBudget` | 聞ける回数。**減らすと難しくなります** |
| `CALLS[].judge` | 受付時の判断の正解（`survey` / `crisis` / `watch`） |
| `CALLS[].crisisSummary` | 班長へ報告するときに表示される状況のまとめ |
| `CALLS[].survey` | 現場の状況。`memo` `people` `equip` `memoTip`（特記事項に入る文章）`crisis` `crisisWhy` |

### 登場人物・資機材

| 設定 | 内容 |
|---|---|
| `ROSTER` | 名簿アプリの初期データ。**実在の方の情報を入れないでください** |
| `VOLUNTEERS` | ボランティア。人数を減らすと**難しく**なります。`ins` を `"未加入"` にするとその人は送り出せません |
| `WALKIN` | 受付で代行入力する方 |
| `EQUIPMENT` `PEOPLE_CHOICES` | 資機材と必要人数の選択肢 |

### 説明・注意点

| 設定 | 内容 |
|---|---|
| `INTRO` | はじめの説明スライド |
| `APPS` | ポータルに並ぶ6つのアプリの説明 |
| `ORIENTATION` | 動画の題名、動画が扱う内容、口頭で伝えるローカルルール（`must:true` は伝え漏れると指摘されます） |
| `SURVEY_CAUTIONS` | 現地調査に出る前の注意点 |
| `SAFETY_CHECK` | 出発前の安全確認 |
| `TYPE_SPEED` | 文字が入力される速さの倍率（`1` が標準、`2` で半分の速さ） |
| `ONLINE_INSURANCE` | 保険のオンライン加入の有無。`false` にすると「窓口で加入手続き」に切り替わります |

## GitHub Pages で公開・更新する

### 更新するとき（いつもの手順）

ファイルを直して、次を実行するだけです。1〜2分で公開URLに反映されます。

```bash
cd /c/Users/user/Documents/saigai-vc-game && git add -A && git commit -m "調整" && git push
```

GitHubのWeb画面から `config.js` を直接編集してもかまいません（鉛筆アイコン → Commit changes）。

### 新しく公開するとき（他の社協で使う場合など）

1. GitHub で **New repository** → 名前を入力 → **Public** → Create
2. **Add file → Upload files** で `index.html` `config.js` `game.js` を上げて Commit
3. **Settings → Pages** → Source を **Deploy from a branch** → Branch **main** / **/(root)** → Save
4. 1〜2分で公開URLが出ます

公開URLをQRコードにして研修資料に載せると、職員がその場でスマホから開けます。

## 使い方の想定

このゲームは、研修の**第1層**にあたります。

| | 内容 | ねらい |
|---|---|---|
| **1. このゲーム** | ひとりで災害VCの1日を体験 | **流れをつかむ** ← いまここ |
| 2. 班別ドリル | 自分の班の操作を本番のkintoneで練習 | 操作を覚える |
| 3. 全体訓練 | 5班に分かれて時間を圧縮した図上訓練 | 連携を体験する |

> **このゲームは「操作研修」ではありません。**
> kintoneの入力は見る・なぞるだけなので、実際に手を動かす練習は第2層で別途行ってください。
> 研修の案内にもそう書き添えることをおすすめします。

ゲームをクリアしてから「災害VC kintone操作マニュアル」を読むと、
どの手順が何のためにあるのかが分かった状態で読めます。

## 注意事項

### 個人情報

- `config.js` に登場人物を追加するときは、**必ず架空の氏名・住所・電話番号**にしてください
- 電話番号は `0877-00-XXXX` `090-0000-XXXX` のような**実在しない番号帯**を使っています
- 公開URLは誰でも見られます。**実際の事例をシナリオに入れる場合は、絶対に公開しないでください**

### 制度に関するメモ

- **ボランティア活動保険**は通常、市区町村社協の窓口で加入しますが、災害が発生するとオンライン加入が実施されます。ゲームもその流れです
- **高速道路の無料措置**は、対象範囲・手続きが災害ごとに国土交通省・NEXCOから示されます。ゲーム内でもその旨を表示しています

参考：ボランティア活動保険 https://www.saigaivc.com/insurance/ ／
災害ボランティア車両 高速道路通行証明書 https://exvolunteer.jp/

### 見た目について（意図的にやっていないこと）

**kintoneの各アプリ画面は、あえてかっこよくしていません。**
本番のkintoneと見た目の差が開くと、「これ見たことある」が起きなくなるためです。
地味なのは欠陥ではなく、そういう作りです。

**登場人物はシルエットのみで、顔は描いていません。**
特定の誰かではなく「そういう立場の人」として見えるようにしています。
被災された方を写実的に描くのは、訓練教材としては扱いが難しいためです。

## 今後の課題

| 課題 | 内容 |
|---|---|
| **内容の正確性レビュー** | 制度や運用の記述が善通寺市社協の実際と合っているか、災害VC担当者・管理職による全文確認が必要 |
| **実機での職員テスト** | 実際の端末（iPhone / Android / 職場PC）で職員に通してもらい、詰まった箇所を記録する |
| **電話シナリオの追加** | `CALLS` を4〜5件に増やし、毎回2件をランダムに選ぶ。ただし危機介入の事例を必ず1件含める抽選ロジックが要ります |
| **色覚特性の確認** | 青と紫が見分けにくい方がいる可能性。アイコンと文字も併記していますが未検証 |
| **難易度「本番」** | 制限時間・同時発生・割り込みを入れたモード。ただし完走率が下がるため別建てにする必要があります |
